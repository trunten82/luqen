## v1 Requirements

### Store and model

- [x] **FP-01**: A dismissal is stored per org, keyed on (org, site URL, rule code, selector), with a REQUIRED non-empty reason (bounded length), the actor and the timestamp.
- [x] **FP-02**: Dismissals are revocable; revoking keeps the record (state change, not delete) so history is never lost.
- [x] **FP-03**: Every mark and unmark is written to an append-only dismissal history (who, when, reason, action) AND to the generic `audit_log`.
- [x] **FP-04**: A dismissal on a selector that cannot identify an element (`html`, `body`, empty — the fallback several engines emit) is REFUSED with a clear message.
- [x] **FP-05**: One pure function applies active dismissals to a raw report and returns the filtered report plus the dismissed occurrences; ONE shared count function derives errors/warnings/notices/total from it, used by every count producer so render-time and stored counts cannot diverge.

### Exclusion everywhere

- [x] **FP-06**: Dismissed issues are excluded from the report detail (Issues, Templates, Pages tabs), print, public report, AI summary input, brand drilldown and email/notification bodies.
- [x] **FP-07**: Dismissed issues are excluded from VPAT/ACR verdicts on every ACR path (report VPAT, share, public ACR, report page, vpat.pdf, vpat-pack.zip, accessibility statement, fleet report). The ACR DISCLOSES, per affected criterion, how many automated findings were dismissed as false positives after review — a conformance document must not silently hide judgements.
- [x] **FP-08**: The stored count columns (`errors`, `warnings`, `notices`, `total_issues`, and `confirmed_violations` where derivable) exclude dismissed issues, so every aggregate surface (home, trends score, badge, fleet, digest, legal exposure, reports list, raw-SQL API, GraphQL, MCP list, scans/trends xlsx) is consistent without parsing JSON. The raw (pre-dismissal) counts remain recoverable.
- [x] **FP-09**: Marking or revoking recomputes the stored counts for that site's existing scans, so the change is visible everywhere immediately, not only on the next scan.
- [x] **FP-10**: Exports exclude dismissed issues (issues.xlsx, report.pdf) and issues.xlsx carries a separate "Dismissed" sheet with reason, actor and date.
- [x] **FP-11**: Surfaces that bypass normalisation honour dismissals: compare (diff ignores dismissed), MCP `dashboard_get_report` / `dashboard_query_issues` / report resource / fleet criterion counts, REST `/api/v1/scans/:id/issues`, fix-PR and bulk-fix candidates (never propose a fix for a dismissed issue).
- [x] **FP-12**: Compliance/regulation matrices do not report a criterion as failing when all of its issues are dismissed.

### Re-application

- [x] **FP-13**: A later scan of the same site automatically applies active dismissals to matching issues (same org, site, code, selector) — counts persisted at scan end already exclude them, and webhook/plugin/completion payloads carry the same counts.

### UI

- [x] **FP-14**: On the report Issues and Templates tabs a permitted user can mark an issue as a false positive; the dialog REQUIRES a reason and PREVIEWS how many occurrences on how many pages of the site the dismissal will cover before confirming.
- [x] **FP-15**: A collapsed "Dismissed" section on the report lists each dismissed issue with its reason, actor and date, and lets a permitted user revoke it (with an optional comment).
- [x] **FP-16**: All new UI text is translated in the 6 dashboard locales; design-system classes only; no inline scripts (CSP); mobile layout works.

### Access and rollout

- [x] **FP-17**: A new permission `issues.dismiss` gates marking and revoking (route-level `requirePermission`, visible in the RBAC matrix). Viewing the Dismissed section needs only report access.
- [x] **FP-18**: DARK LAUNCH: at first `issues.dismiss` is held only by global (dashboard) admins — verified that no customer user is a global admin — so it can run in prod on a test org. Alessandro receives a test link; only after his approval is the permission granted to org Owner/Admin roles.

## v2 Requirements (deferred)

## Out of Scope

| Feature | Reason |
|---------|--------|
| WordPress plugin mirror | Owner ruling 2026-10-08 |
| Rewriting stored issues in `json_report` | Destroys evidence and makes revoke lossy; apply at read + rewrite only derived count columns |
| Brand score (`brand_scores`) changes | Separate concern driven by brand matching, not WCAG findings |
| Per-rule (all selectors) or per-org-wide suppression | Too broad for a judgement made on one element; not in the ruling |
